# Plan 01-03: Symlink and Directory Junction Safe Deletion Logic

## 1. Goal
Prevent permanent cleanup operations from recursively traversing and deleting the contents of target directories when removing a symbolic link or Windows directory junction.

## 2. Context & Locations
- File: `src-tauri/src/services/cleanup/mod.rs` (around line 375-385)
- Currently:
  ```rust
  if path_obj.is_dir() {
      fs::remove_dir_all(path_obj)?;
  } else {
      fs::remove_file(path_obj)?;
  }
  ```
  `is_dir()` follows symlinks! If `path_obj` is a directory symlink, `remove_dir_all` deletes the actual files inside the referenced directory rather than unlinking the symlink itself.

## 3. Implementation Tasks
- [ ] Inspect metadata with `fs::symlink_metadata(path_obj)`:
  - If `file_type().is_symlink()` is true:
    - On Unix: Call `fs::remove_file(path_obj)` to unlink the symlink without touching the target.
    - On Windows: If it is a directory junction or directory symlink, call `std::fs::remove_dir(path_obj)` (which unlinks the junction without recursing), otherwise `fs::remove_file(path_obj)`.
  - Only call `fs::remove_dir_all(path_obj)` if it is an actual physical directory (`is_dir() && !is_symlink`).
- [ ] Add unit test verifying that deleting a directory symlink removes the symlink pointer while leaving the target folder and its contained files intact.

## 4. Verification Criteria
- `cargo test --manifest-path src-tauri/Cargo.toml` passes.
- Symlinks pointing to directories are safely unlinked without deleting target contents.
