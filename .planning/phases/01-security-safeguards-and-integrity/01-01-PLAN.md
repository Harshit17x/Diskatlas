# Plan 01-01: SQL Query Parameterization

## 1. Goal
Eliminate all instances of raw SQL string interpolation with user or IPC-controlled parameters, replacing them with Rusqlite parameterized queries (`params![]` or positional bindings `?1, ?2`).

## 2. Context & Locations
1. `src-tauri/src/services/cleanup/mod.rs` (lines ~520-555):
   `get_cleanup_audit_history` builds `count_sql` and `query_sql` by formatting `query.session_id` and `query.status`.
2. `src-tauri/src/services/analysis/mod.rs` (lines ~250-270):
   `find_duplicates` formats `query.extension` into `stage1_sql`.

## 3. Implementation Tasks
- [ ] Refactor `src-tauri/src/services/cleanup/mod.rs`:
  - Dynamically accumulate parameter references (`Vec<&dyn rusqlite::ToSql>`).
  - Use `?` placeholders for `session_id` and `status` filters.
  - Bind parameters cleanly to `conn.prepare(&count_sql)?.query_row(rusqlite::params_from_iter(...))` and `conn.prepare(&query_sql)?.query_map(...)`.
- [ ] Refactor `src-tauri/src/services/analysis/mod.rs`:
  - Bind `query.extension` with positional placeholder `?3` instead of string interpolation.
- [ ] Add unit tests verifying that queries with special characters (quotes, semicolons, dashes) do not trigger SQL syntax errors or query injection.

## 4. Verification Criteria
- `cargo test --manifest-path src-tauri/Cargo.toml` passes with zero failures.
- No instances of `format!("... WHERE ... = '{}'")` remain in backend service queries.
