# Plan 01-05: Drive Scanner Target Initialization & State Reset

## 1. Goal
Ensure drive scanning and running the drive scanner is immediately accessible and reliable:
1. Provide a working `npm run drive` script in `package.json` that launches Tauri in dev mode.
2. Fix modal state reset in `openScanModal` so that completed scan states from prior runs do not block or mask new drive scan operations.
3. Automatically match and sync valid drive IDs and root mount points so the "Start Scan" button is never improperly disabled.

## 2. Context & Root Causes
- If a previous scan had finished, `summary` remained non-null in `scanStore`, causing `ScanModal` to open directly into "Scan Completed" rather than the interactive configuration view.
- When `targetDriveId` had an initial dummy value (`DRIVE_PRIMARY`), `ScanModal` failed to sync to the first detected volume (`drives[0]`), leaving `targetPath` empty and disabling the Start button.
- Developers attempting to run `npm run drive` in the terminal encountered `npm ERR! missing script: drive`.

## 3. Implementation Tasks
- [x] Add `"drive": "node ./node_modules/@tauri-apps/cli/tauri.js dev"` to `package.json`.
- [x] Refactor `openScanModal` in `src/stores/scanStore.ts` to reset `summary: null` and `error: null` when initiating a new scan.
- [x] Update `src/features/scanner/ScanModal.tsx` `useEffect` to verify whether `targetDriveId` matches an existing drive in `drives`, automatically selecting `drives[0]` and setting `targetPath` to `drives[0].mountPoint` if unselected or empty.
- [x] Update `src/features/explorer/DriveExplorerView.tsx` to provide fallback drive mount points when opening the scan modal.

## 4. Verification Criteria
- `npm run drive -- --help` executes successfully.
- `npm run build` succeeds with zero TypeScript errors.
- Clicking "Scan Drive" or "Scan" opens the modal in clean setup mode, with target drive and root path populated, enabling immediate scan execution.
